# Changelog

## 0.3.0 (2026-11-09)

Inboxes: data now arrives without an upload, and scans become values through local OCR or your own agent. Upgrade in place by changing the image tag to `drumsergio/ownhealth:0.3.0`; four new migrations (1000, 1001, 1050, 1051) apply at start, and passwords, passkeys, access tokens and every profile's `state_hash` stay as they were. Set `OWNHEALTH_SECRETS_KEY` (`openssl rand -base64 32`) before you add an inbox that needs a password or token ([.env.example](.env.example)). The watched folder `./inbox` must be writable by the app's user: run `mkdir -p inbox && sudo chown 10001:10001 inbox` next to `compose.yaml` before you upgrade, or the folder inbox shows as failing. The default image grows from 352 MB to 364 MB unpacked (79 MB to 84 MB to download, arm64); the `-ocr` variant with the engine and models is 436 MB (109 MB to download).

- **Email.** OwnHealth polls a mailbox of its own every minute over IMAP (TLS, STARTTLS, or plain only to a private address). Mail from an allowed sender, with its own server's DMARC, SPF or DKIM pass, goes to that sender's profile; everything else waits in quarantine and is never read until a person releases it, with "allow sender" in one click. Locked lab PDFs open with passwords kept per sender, encrypted at rest.
- **Watched folder, Paperless-ngx, phone.** A scanner or synced folder (one subfolder per profile), the Paperless "Document Added" webhook with the original pulled over its API and a link back, the Android share target and an iOS Shortcut recipe. Dedup now has three levels: file hash, page fingerprint (a scan or photo of a report you hold is flagged "probably the same" once OCR has read its words; the picture alone never decides, since every report from one lab looks alike), and the observation match.
- **OCR** in the `drumsergio/ownhealth:0.3.0-ocr` image and the `ocr` compose profile: PP-OCRv5 through ONNX Runtime, in Rust, on CPU. Row F1 0.954 on the scanned and photographed eval set at under a second a page ([docs/ocr-benchmark.md](docs/ocr-benchmark.md)). Every OCR value is checked against the page's words. The default image carries no models; the `-ocr` image ships the licence texts of PaddleOCR (the models) and ONNX Runtime under `/usr/share/doc/`.
- **Agent extraction.** Without OCR, scans wait as pending documents. `list_pending_documents` and `get_document_page` let your own agent read them over MCP and `propose` values with page and box; ungrounded values are flagged (a value counts only on a line that prints its analyte's name, and inside the box when the agent gives one), and the review queue shows which documents of that profile were in the agent's context. A page nothing was extracted from (queued for OCR, its pending item dismissed) needs every read category and the agents switch, like a pending page ([docs/agent-extraction.md](docs/agent-extraction.md)).
- **OAuth 2.1 for MCP.** Protected-resource metadata (RFC 9728), audience checks (RFC 8707), PKCE S256 and Client ID Metadata Documents, so claude.ai and Claude Code connect with no client registration. A native client's loopback redirect matches on any port (RFC 8252); a client may register only https, loopback http or a reverse-domain app scheme as its redirect. A refused authorization request is shown as an error page, never redirected, so `/oauth/authorize` cannot be used to bounce people to another site; open requests are capped and lapsed ones purged, so the unauthenticated endpoint cannot fill the database. A tool outside the scopes you approved answers `scope_missing`; to widen access, connect the client again and tick more scopes. OAuth runs only behind https.
- **Wearables and CGM.** Health Auto Export push (JSON v2), Gadgetbridge database import, Nightscout pull (v1 and v3, FreeStyle Libre through nightscout-connect), and a CGM summary per the HL7 CGM IG: time in ranges, mean glucose, GMI, and the 70% wear validity rule over 14 days. Wear counts the readings against the sensor's interval, so a sensor read every minute whose timestamps drift a few seconds still shows full wear. Resting heart rate pushed from west of UTC stays on its own day, and a raw push is kept 30 days, then removed (its samples stay).
- **Inbox screen and health.** Sources, last run, errors, quarantine and push tokens in one screen, in Spanish and English; `GET /api/inboxes/{id}/health` with the last successful sync and whether the last run was ok, partial or failed, also as Prometheus text, for alerting ([deploy/README.md](deploy/README.md#monitoring-the-inboxes)). A run where every item failed counts as a failure, and skipped attachments or points show as a partial run, never as silence.
- **Safer inbox settings.** Changing where a mailbox, Paperless or Nightscout connects needs a fresh step-up and the password or token again, so a stolen session cannot point a stored secret at another server. "Allow sender" needs the mailbox's trusted receiving server to be set. Removing a sender needs the same right and step-up as adding one, and "allow sender" on a release refuses a sender already listed for another profile. A Paperless or Nightscout on a public address must use https, so its token never crosses the internet in clear. A forged envelope sender with a quoted `;` cannot add a DKIM pass to the trusted Authentication-Results header, and a held message with two From addresses shows both. A folder source reads a profile's folder only when its creator manages that profile, and its subfolder cannot point at `.done`, `.failed` or another profile's folder; the demo never reads the folder.
- **Review and Inbox screen fixes.** An agent's lab values show row by row next to the page, each with its "found on the page" flag; only rows found on the page start ticked, and Accept writes only the ticked rows. Editing an inbox keeps the settings the form does not show (Paperless tag routing, Nightscout backfill, a mailbox CA file). Every inbox can get a token, a polled one for its monitor. Replacing a live token, removing a sender and deleting a PDF password each ask for a second click. Mail held because the mailbox has no trusted authserv-id reads "not authenticated" in amber, not "failed DKIM/SPF". An incomplete CGM summary shows no time-in-range figures instead of 0 %. The UI cannot be framed by another site.
- **Nothing silently stuck.** A mailbox whose done folder cannot be used fails its run and names the folder, and new mail is read before handled mail left behind. A watched-folder file stays in place when OwnHealth itself fails (database restart, full disk) instead of going to `.failed`, and a file that vanishes mid-scan or turns into a pipe no longer stops the poll. Paperless pulls also fetch documents tagged in bulk, whose modified date does not change. A locked PDF that came before its password opens as soon as the password is added.
- **Scans keep their values.** A scanned report moved to another profile, or uploaded again after a retract, is read by OCR again for its new owner, instead of losing its values. A page OCR cannot read joins the document's pending item next to the pages it read without a table, each with its own reason. A value already stored is cited from a new document only when the row passes every check and the document names this person; otherwise it waits in review. A result printed with a date and no time is compared with the values stored one UTC day either side, so the same draw entered with its local time is not stored twice.
- **Deleting a profile always works.** A duplicate value linked from a second source, or an OAuth connection that named the profile (live or revoked), no longer blocks the delete. Connections drop the profile, and one left with no profile is revoked.
- **Recipes** for email, Paperless-ngx, scanner to folder, Health Auto Export, Gadgetbridge, Nightscout, the iOS Shortcut and the claude.ai connector ([docs/recipes](docs/recipes/README.md)).

Known limits: no IMAP IDLE (a poll a minute); the text body of a mail is kept in the stored message, not imported as its own document; HEIC photos are not read (the Shortcut converts to JPEG); Paperless gets no tag written back. Measured exit criteria: [docs/v0.2-exit-criteria.md](docs/v0.2-exit-criteria.md).

## 0.2.0 (2026-11-08)

The backend is now Rust: one binary with the web UI built in, in place of the Python 3.13 app. Same features, same data. Upgrade in place by changing the image tag to `drumsergio/ownhealth:0.2.0`; there are no new migrations, so a 0.1.1 database is already up to date, and passkeys, passwords, sessions and access tokens keep working. The image went from 586 MB to 348 MB unpacked (129 MB to 79 MB to download, arm64).

- **Same answers.** The REST API, the MCP tools, their errors and scopes, the cookies, the blob layout and the `state_hash` of every profile are the ones 0.1.1 gave. A black-box suite of 79 tests with answers recorded from 0.1.1 passes on both releases.
- **Stack.** axum and tokio, sqlx for Postgres, rmcp (the official Rust MCP SDK), PDFium through pdfium-render for lab PDFs, noodles for the VCF and its tabix index, webauthn-rs for passkeys.
- **Re-imports.** A lab PDF read by 0.2.0 records `pdfium` as its extraction engine, so forcing a re-import of a document 0.1.1 read adds a new extraction run. Its rows are the same.
- **Uploads.** A form field other than a file is refused past 1 MiB, and a form past 1000 fields or 1000 files, as 0.1.1 did.
- **Logs.** One line per request with method, route, status and latency, never the query string. Upload leftovers in `/data/blobs/tmp` that a killed process left behind are removed after an hour.
- **Homelab backups.** The restic repository and its S3 keys move from `.env` to `restic.env`, which only the `admin` service reads, so the app container no longer holds the keys to the backups. An install that keeps them in `.env` still works; move the lines to take them away from the app ([deploy/README.md](deploy/README.md#homelab-setup)).

## 0.1.1 (2026-11-08)

Fixes from a full CodeRabbit review of 0.1.0, plus places where the code disagreed with the design docs. No migrations; an existing 0.1.0 install upgrades in place.

- **Security.** Adding a passkey or linking an OIDC provider needs a fresh login; the OIDC callback only counts in the browser that started it; a caregiver can no longer take over a managed profile with a claim invite; document search no longer matches or quotes sensitive pages without `read:sensitive`; document bytes are sent `no-store`; a fact can no longer create a source on another profile.
- **Genome.** Lookups no longer reveal that a withheld finding sits at a position; minors are also shielded from carrier-panel genes; the importer recomputes fact ids, caps confidence per assay, checks imputed sites and keeps sensitive facts inside their gene spans; drug guidance comes from the newest CPIC version.
- **Drug check and status.** CYP2D6 phenoconversion bands follow CPIC's open bounds, so no activity score is left without a phenotype; medication matching uses whole words; `get_health_status` stays under 2 KB with long notes; `check_drug` accepts its own paging cursor.
- **Data.** Duplicate detection considers method, comparator and source; the received UCUM unit is kept like the received LOINC code; trend statistics never mix units.
- **Robustness and UI.** Oversized limits and windows answer 422 instead of 500; a failed export leaves no file behind; browser reads are audited as `ui`; a new relative's profile starts with a guardian (profiles created on 0.1.0 may still have none); UI fixes across the review queue, genome, settings and charts.

## 0.1.0 (2026-11-08)

The first release you can run: `docker compose up` with one app image and Postgres 17.

- **Imports.** Lab PDFs with a text layer (rows read with page and position, coded to LOINC, units converted, checked against the printed range, auto-accepted only when every check passes, else the review queue). Apple Health `export.zip`, FHIR R4 and IPS bundles, manual entry, and OwnGenome `genome-facts.json` with its VCF. Scans and photos wait as pending documents for an agent to read over MCP.
- **Status.** One card per body system (OK, Watch, Out, Stale, No data) from a cited YAML rule pack, with a reproducible `state_hash`. Drug check with CPIC level A quotes, current medications, relevant labs and phenoconversion.
- **MCP** at `/mcp`: `get_health_status`, `search_observations`, `get_trend`, `get_genome_findings`, `lookup_variant`, `check_drug`, `get_source`, `propose`. Hashed scoped PATs, scope-filtered `tools/list`, `untrusted_text` on free text, agent writes only into the review queue, rate limits, audit log.
- **Security.** Passkeys with recovery codes, step-up, household roles, full export (FHIR NDJSON plus originals) from the UI only.
- **UI.** Dark theme, Spanish and English, built to match the mockup.

Known limits: no curated rsID index yet, so rsID lookups outside your own facts file answer `rsid_unknown`; lab coverage is the synthetic eval set; no OCR (v0.2). Measured exit criteria: [docs/v0.1-exit-criteria.md](docs/v0.1-exit-criteria.md).
